# 07 · 技术架构与多平台

## 1. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript 5.9 | 类型安全，编辑器提示完整 |
| 渲染引擎 | **Phaser 3.90** | 成熟的 2D 引擎，WebGL 渲染且能自动退回 Canvas，触摸支持好，资料多 |
| 构建 | Vite | 开发时热更新快，输出纯静态文件 |
| 界面 | 原生 HTML + CSS，叠在画布上 | 响应式布局和文字渲染都比在画布里画方便，也更容易做无障碍 |
| 测试 | Vitest | 测试纯逻辑和平衡模拟 |
| 素材转换 | 运行时光栅化 | 启动时把 SVG 按图层拆开，按屏幕像素密度和棋盘缩放画成纹理图集 |

## 2. 多平台路线

**一套 Web 代码覆盖所有平台**，按阶段推进：

| 阶段 | 形态 | 技术 | 说明 |
|---|---|---|---|
| ① | 网页 | Vite 静态站点 | 部署到 Cloudflare Pages、Vercel 或 GitHub Pages |
| ② | **PWA** | manifest + Service Worker（vite-plugin-pwa） | 手机可以"添加到主屏幕"，全屏运行、离线可玩 |
| ③ | iOS / Android 应用 | **Capacitor** | 同一份构建产物套原生壳，可上架商店；可选接入震动反馈和原生存档 |
| ④ | Windows / macOS / Linux | **Tauri**（安装包约 10MB）或 Electron | 可上架 Steam，接入 Steam 成就需要额外插件 |

### 2.1 从第一天就要遵守的多端约束
1. **输入**：只用指针事件（Pointer Events），鼠标、触摸、触控笔走同一套代码；任何信息都不能只靠悬停才看得到。
2. **布局**：横屏和竖屏两套 CSS，用宽高比切换；适配刘海屏安全区（`env(safe-area-inset-*)`）。
3. **清晰度**：按 `devicePixelRatio` 选 1×、2×、3× 图集；画布分辨率跟随像素密度，最高 3 倍。
4. **防误操作**：画布设 `touch-action: none`，禁用双指缩放、长按菜单和文字选中。
5. **生命周期**：切到后台（`visibilitychange`）自动暂停；回到前台不会自动继续，由玩家点"继续"。
6. **存档容错**：读写 localStorage 都包在 try/catch 里，失败时游戏照常运行，只是不保存。
7. **音频**：手机浏览器要求用户先点击一次才能出声，所以首次点击时才解锁音频。

### 2.2 性能预算（目标：中端手机 60fps）
| 项目 | 上限 / 做法 |
|---|---|
| 同屏敌人 | 150 个（超出时合并成兵团，见第 04 章） |
| 同屏子弹 | 300 个，对象池复用 |
| 粒子 | 600 个，低画质下减半 |
| 绘制批次 | 所有素材打成一张图集，尽量一次批量绘制 |
| 碰撞 / 选目标 | 网格分桶查询，不做每个塔对每个敌人的全量遍历 |
| 画质选项 | 高 / 低：低画质关闭发光层和光环粒子，渲染分辨率最高 2 倍 |

## 3. 代码架构

```
desk-defense/
├── docs/                    # 设计文档（本目录）
├── art/                     # SVG 源文件 + gallery.html 预览页
├── scripts/
│   ├── simulate.ts          # 无界面的平衡模拟（bots/ 下是机器人策略）
│   ├── bench.ts             # 各塔性价比与传奇分支对比
│   └── build-gallery.mjs    # 美术预览页
├── src/
│   ├── main.ts
│   ├── config/              # ★ 全部数值配置（带类型的 TS 数据），调平衡只改这里
│   ├── core/                # ★ 纯逻辑，不引用 Phaser，可以在 Node 里运行
│   │   ├── World.ts         # 一局游戏的完整状态，固定步长 update(dt)
│   │   ├── Grid.ts          # 网格、障碍、放置校验
│   │   ├── FlowField.ts     # Dijkstra 流场
│   │   ├── Rng.ts           # 带种子的随机数（mulberry32）
│   │   ├── WaveGen.ts       # 无尽波次生成（第 04 章）
│   │   ├── Scaling.ts       # 成长公式
│   │   ├── combat/          # 伤害、护甲、护盾、状态效果、选目标
│   │   ├── towers/          # 塔的行为（按类型）、经验、升级、出售
│   │   ├── enemies/         # 敌人行为、词缀、Boss 技能
│   │   ├── skills/          # 主动技能
│   │   ├── perks/           # 局内增益
│   │   └── events.ts        # 逻辑层向外发出的事件（命中、死亡、升级……）
│   ├── render/              # Phaser 场景：订阅事件，按状态绘制，不修改状态
│   │   ├── BoardScene.ts
│   │   ├── sprites/         # 把 SVG 图层组装成可动画的对象
│   │   └── fx/              # 粒子、光束、冲击环
│   ├── input/               # 指针和键盘 → 指令（放塔、升级、技能…）
│   ├── ui/                  # HTML 界面（状态栏、塔栏、信息面板、菜单）
│   └── meta/                # 存档、永久天赋、排行榜、设置
└── tests/
```

### 3.1 核心原则
1. **逻辑和渲染分离**：`core/` 不知道 Phaser 的存在，渲染层只读状态、听事件。好处：
   - 平衡模拟在 Node 里几秒钟就能跑完 100 波
   - 加速只是每帧多跑几次逻辑，结果和 1× 速度完全一致
   - 换渲染引擎或做服务器校验时，不需要改逻辑
2. **固定步长**：逻辑每步 1/60 秒，渲染时对位置做插值。
3. **指令驱动**：玩家的所有操作都变成指令（`{t: 帧号, type: 'place', tower, x, y}`）。**种子加指令序列就能完整复现一局**，可以用来做回放、找 bug 和线上排行榜校验。
4. **数据驱动**：塔、敌人、词缀、技能、增益都写在 JSON 里，行为用"类型 + 参数"组合，新增一种敌人尽量不改代码。
5. **确定性**：逻辑里禁止使用 `Math.random()` 和 `Date.now()`，一律用 `Rng` 和帧号。

### 3.2 平衡模拟（scripts/simulate.ts）
- 读入一份"策略脚本"，比如"前 5 波铺 6 座铅笔 + 一段迷宫，之后按优先级升级"。
- 对每个难度跑 N 个种子，输出每波的金币、漏怪数、塔的平均等级，以及撑到的波数分布。
- 校准目标：
  - 普通难度，中等策略，平均撑到第 45～60 波
  - 简单难度，新手策略，能撑过第 20 波
  - 魔境 I，优秀策略，平均撑到第 30～40 波
- 结果输出成 CSV，并生成一张图表（HTML 页面），比较调整配置前后的变化。
- 运行：`npm run sim -- [--scenario calib|endless|campaign|xp|ladder|custom] [--seeds 8]`。策略机器人在 `scripts/bots/`（newbie / medium / expert），输出到 `scripts/out/`（runs.csv、waves.csv、summary.json、report.html）。`--save-baseline` 保存基线，之后的报告叠加对比；`--patch '{"presets.hard.hpMul":1.2}'` 可在不改文件的情况下试调配置。塔的性价比与传奇分支对比：`npx vite-node scripts/bench.ts`。

### 3.3 存档格式（localStorage）
```jsonc
{
  "v": 1,
  "campaign": { "1-1": 3, "1-2": 2 },          // 每关星数
  "currency": { "star": 12, "ink": 340 },
  "talents": { "wallet": 2, "bandaid": 1 },
  "skills": { "unlocked": ["eraser_strike","bell"], "levels": {"bell": 2} },
  "unlockedDifficulty": ["easy","normal","hard"],
  "abyssLevel": 0,
  "leaderboard": { "normal": [{ "wave": 52, "score": 8123, "seed": "a1b2", "date": "2026-11-19" }] },
  "settings": { "quality": "high", "sfx": 0.8, "music": 0.5, "lang": "zh" },
  "midRun": null                               // 中途存档：种子 + 指令序列
}
```
- **中途存档**：在每波结束时自动保存"种子 + 指令序列"。手机上被杀掉进程后，可以从上一波结束的地方继续。

## 4. 质量保障
| 类别 | 内容 |
|---|---|
| 单元测试 | 流场、放置校验、伤害计算、经验和升级费用、出售返还、波次生成（同一种子结果必须一致） |
| 回放测试 | 录下几局的指令序列，每次改代码后重放，检查结果是否和录制时一致 |
| 平衡回归 | 每次修改配置后跑模拟，对比关键指标 |
| 多端检查 | iPhone Safari、安卓 Chrome、iPad 横竖屏、桌面 Chrome / Safari / Firefox |

## 5. 开发里程碑

| 里程碑 | 内容 | 完成标准 |
|---|---|---|
| M1 骨架 | Vite 项目、响应式布局、棋盘、放墙、流场、放置校验 | 手机和电脑上都能放墙，敌人会绕路 |
| M2 战斗 | 铅笔、订书机、胶水、台灯；5 种基础敌人；金币和生命 | 能打完战役 1-1 |
| M3 成长 | 经验、升级、4 种形态、出售规则、相邻加成 | 塔能从 Lv1 升到 Lv10 并选择分支 |
| M4 无尽 | 波次生成、难度预设、魔境、精英词缀、Boss、兵团合并 | 无尽模式能跑到第 100 波 |
| M5 能力 | 9 个主动技能、局内增益、永久天赋、存档 | 完整的局外循环 |
| M6 内容 | 全部 11 座塔、12 种敌人、4 个 Boss、3 个战役章节 | 内容齐全 |
| M7 平衡与打磨 | 模拟调参、特效、音效、新手引导、PWA | 手机能安装到主屏幕并离线游玩 |
| M8 发布 | 网页上线；用 Capacitor 和 Tauri 打包 | 至少一个平台正式发布 |
