# 12 · 全服排行榜（免费版）

> 目标：在 Cloudflare **免费计划**内，给无尽、每日挑战和战役加上全服排行榜。
> 第一阶段只做「轻量校验 + 保存回放数据」；第二阶段的服务端回放校验**已实现但默认关闭**（需要付费计划的 CPU 时间，见 §5.2）。
>
> 2026-11 精简（§4）：只剩 **无尽 / 每日 / 战役** 三类榜；成绩**默认自动上传**（默认昵称，不弹框）；
> AI 辅助（「让 AI 替我玩」/「AI 参战」）的成绩**进同一张榜**，只是带「AI 辅助」标记，可一键隐藏。

## 1. 架构

```
浏览器（Vite 静态包 + PWA）                     Cloudflare Pages
┌──────────────────────────────┐   同源 fetch   ┌───────────────────────────────┐
│ src/meta/online.ts            │ ────────────▶ │ functions/api/*（Pages Functions）│
│  · 设备 id / 昵称 / 离线队列   │               │  · _middleware：同源限制 + 兜底错误 │
│  · gzip 压缩指令日志           │               │  · _lib/handlers：校验 / 限流      │
│ src/shared/*（与服务端共用）   │ ◀──────────── │  · _lib/db：D1 SQL                │
└──────────────────────────────┘    JSON        └──────────────┬────────────────┘
                                                               │ D1 绑定 DB
                                                     ┌─────────▼─────────┐

```

共用代码只用浏览器和 Workers 都有的 API（`crypto.subtle`、`CompressionStream`、`btoa`……），
运行时只依赖 `src/config/difficulty.ts`（得分倍率与 core 同源）。
core 新增了技能 / 天赋 / 指令类型而 `src/shared` 没跟上时，`tsc` 会在 `_Check*` 类型处报错。

`functions/_lib/admin.ts` 用 `import()` 惰性加载 core，关闭时完全不执行 core 的代码，其他接口不受影响。
本地确认能打包：`npx wrangler@4 pages functions build functions --outdir /tmp/fb`（约 450 KB）。

## 2. API

所有接口只接受**同源**请求（带 `Origin` 且与站点不同源、`Sec-Fetch-Site: cross-site`、`OPTIONS` 预检一律 403，且不返回任何 CORS 头）。
例外：原生 App 壳的固定来源 `capacitor://localhost`、`https://localhost`、`tauri://localhost`、`http://tauri.localhost`
（`functions/_lib/http.ts` `APP_ORIGINS`）——预检回 204（`GET, POST` / `Content-Type, Accept`），其他响应补 `Access-Control-Allow-Origin` + `Vary: Origin`。
错误统一为 `{ error: 代码, message: 中文提示, retryAfter? }`。

| 代码 | HTTP | 含义 | 客户端处理 |
|---|---|---|---|
| `bad_request` | 400 | 数据不合法（得分不符、榜键不对……） | 丢弃，提示 message |
| `version` | 409 | 客户端版本不是当前版本 | 丢弃，提示刷新 |
| `too_large` | 413 | 请求体 / 日志过大 | 丢弃 |
| `turnstile` | 403 | 人机验证未通过 | 进队列，稍后重试 |
| `forbidden` | 403 | 跨站请求 | — |
| `rate_limited` | 429 | 提交太频繁（带 `Retry-After`） | 进队列 |
| `not_found` | 404 | 成绩 / 接口不存在 | — |
| `not_configured` | 503 | 没绑定 D1 | 显示「在线功能不可用」 |
| `internal` | 500 | 服务器错误 | 进队列 |

### 2.1 `POST /api/runs` 提交成绩

```jsonc
{
  "nickname": "小明",                       // 1–12 字
  "deviceId": "uuid v4",                    // 客户端随机生成，服务端只存哈希
  "board": "endless",                       // 见 §4：endless / daily:<日期> / campaign:<章节>（旧榜键会被归一）
  "opts": { /* RunOptions，含 seed */ },
  "seed": "k3x9ab",
  "log": { "gz": "H4sI…" },                 // world.log → JSON → gzip → base64；不支持压缩时直接发数组
  "result": { "wave": 42, "score": 12345, "kills": 3456, "lives": 0, "gold": 230, "won": false, "ticks": 98765,
              "cleared": 42, "bonus": 0,    // cleared / bonus 可选（见 §5.1）
              "maxLives": 23, "stars": 3 }, // 仅战役：通关时的生命上限与评星（服务端按 starsFor 重算核对）
  "gameVersion": "0.1.0+c1",
  "turnstileToken": "…",                    // 只有服务端配置了 TURNSTILE_SECRET 才需要
  "aiAssist": { "model": "离线演示", "botShare": 0.3 }, // 可选：用过「让 AI 替我玩」（只用军师不发）；botShare 可选（见 §4.1）
  "agent": { "provider": "claude-native", "model": "…", "mode": "pause", "botShare": 0.05, "decisions": 40 }
                                            // 可选：「AI 参战」（全程 AI）；二者都会让成绩带「AI 辅助」标记
}
```

返回 `201`（刷新纪录）或 `200`（没超过自己的旧纪录）：
`{ id, rank, total, improved, status: 'pending' }` —— `id / rank` 是本设备在该榜**当前最佳**成绩的。

处理顺序（全部在免费计划约 10 ms CPU 内）：
1. 请求体 ≤ 320 KB → 解析 JSON
2. **限流**（IP 和设备各计一次，见 §5.3）——放在详细校验之前，垃圾请求也计数
3. `checkSubmission`：schema、版本、昵称、榜键与 opts 一致、种子规则、得分重算、结果合理性
4. Turnstile（可选）
5. 解压日志（原文 ≤ 200 KB，超过立即中止）→ `checkLog`：帧号单调、不晚于结束帧、指令数与时长相称
6. 条件 UPSERT（§3），算名次，清掉该榜的边缘缓存

### 2.2 `GET /api/leaderboard?board=…&limit=20[&around=<deviceId>][&hideAi=1]`

`{ board, rows: LeaderRow[], total, hideAi, generatedAt, me? }`，`limit` 1–100。`board` 也接受旧榜键（归一后返回新榜）。
`LeaderRow` = `{ rank, id, nickname, score, wave, kills, lives, map, difficulty, abyssLevel?, stars, won, status, createdAt, ai, aiModel?, agent?, botHeavy? }`。
`hideAi=1` 时只看真人成绩（`ai = 0`），名次和总数也只在真人成绩里算。
前 N 名按 10/20/50/100 档位 × 是否隐藏 AI 存进 Cloudflare 边缘缓存（Cache API）30 秒，响应带 `Cache-Control: public, max-age=30`；
有人刷新纪录时清掉该榜所有档位（只清当前机房，其它机房最多旧 30 秒）。
带 `around` 时额外返回调用者的最佳成绩和名次（`me`，没有成绩为 `null`；不隐藏 AI 时取真人最佳与 AI 辅助最佳里排名更靠前的一条），响应改为 `private, max-age=10`。

排序：**评星降序**（只有战役有星，其它榜恒为 0）→ 分数降序 → 波数降序 → 提交时间升序 → id。`status = 'rejected'` 的成绩不显示。

### 2.3 `GET /api/runs/:id`

`{ id, board, nickname, opts, seed, logGz, result, gameVersion, status, createdAt, ai, aiModel?, agent? }`，用于观看回放
（客户端 `fetchRun` 会解压出 `log`，`runToMidRun` 转成 midrun 结构后用 `replayAsync` 快进）。
同一设备刷新纪录后旧 id 会失效（404）。缓存 5 分钟。

### 2.4 `GET /api/daily`

`{ day, seed, map, difficulty, board, pure: true, autoWave: true }`，按北京时间日期推算，缓存到零点（最多 5 分钟）。

### 2.5 `GET /api/status`

`{ ok, gameVersion, turnstileSiteKey, daily }`——客户端启动时用它探测在线功能是否可用。

### 2.6 `POST /api/admin/verify?limit=5`（第二阶段，默认关闭）

头：`X-Admin-Token: <ADMIN_TOKEN>`（或 `Authorization: Bearer …`）。`REPLAY_VERIFY` 不是 `'1'` 或没设 `ADMIN_TOKEN` 时返回 404（与不存在的接口一样）；口令错 403。
每次处理最早提交的 `limit` 条（1–50）**当前版本**的 pending 成绩，返回
`{ gameVersion, processed, verified, rejected, remaining, items: [{ id, board, status, reason?, ms }] }`；单次请求墙钟预算 20 s，处理不完的下次再来。
详见 §5.2。

其它 `/api/*` 路径返回 JSON 404（不会落到静态站点的 `index.html`）。

## 3. 数据表

见 `migrations/0001_init.sql`、`0002_ai_board.sql`、`0003_simple_boards.sql`。第二阶段与兜底标记**不需要新迁移**：
`status / reject_reason / verified_at` 在 0001 就有，兜底占比复用 0002 的 `agent_bot_share`。

**runs**：`id, board, day, nickname, device_hash, score, wave, kills, lives, seed, map, difficulty, abyss, pure, auto_wave, game_version, opts_json, result_json, log_gz, log_bytes, status, reject_reason, verified_at, created_at, ip_hash`
+ AI 参战（0002）：`agent_provider, agent_model, agent_mode, agent_bot_share, agent_json`
  （`agent_bot_share` 也用于中途接管的 AI 辅助局：此时 `agent_provider` 为 NULL；旧客户端 / 不知道时为 NULL）
+ 精简榜单（0003）：`ai`（1 = AI 辅助）、`ai_model`、`stars`（战役评星，失败 0）、`won`（战役通关 1）

- `UNIQUE(board, device_hash)`：**每台设备每个榜只存一条最佳成绩——真人与 AI 辅助各一条**。
  真人成绩 `device_hash = sha256(salt|dev|uuid)`，AI 辅助成绩 `= sha256(salt|dev|uuid|ai)`，两者互不覆盖，
  所以「隐藏 AI 辅助」时自己的真人成绩不会被 AI 成绩顶掉。提交时：
  ```sql
  INSERT … ON CONFLICT(board, device_hash) DO UPDATE SET …
  WHERE excluded.stars > runs.stars
     OR (excluded.stars = runs.stars AND (excluded.score > runs.score
         OR (excluded.score = runs.score AND excluded.wave > runs.wave)))
     OR runs.status = 'rejected'
  RETURNING id
  ```
  没覆盖时只更新昵称。这样排行查询就是简单的 `ORDER BY … LIMIT`，表的大小 ≈ 玩家数 × 玩过的榜数 × 2，免费额度（5 GB）足够。
  代价：被覆盖的旧成绩不再保留（第二阶段如果新成绩被判作弊，这台设备在该榜就没有成绩了，需要重新打）。
- 索引：`(board, stars DESC, score DESC, wave DESC, created_at, id)` 支撑前 N 名和名次计数；`(board, ai, …)` 给「隐藏 AI」；
  `(status, created_at)` 给第二阶段的校验队列；`(day)` 方便清理旧的每日榜。
- `status`：`pending`（刚提交）→ 第二阶段回放后变成 `verified` 或 `rejected`。

**rate_limits**：`key, window_start, count`，固定窗口计数，见 §5.3。

### 3.1 迁移 0003（旧榜 → 新榜）

`migrations/0003_simple_boards.sql`（由负责人执行：`npx wrangler@4 d1 migrations apply desk-defense --remote`）：

1. 加列 `ai / ai_model / stars / won`；
2. 旧 `ai:` 榜（以及带 `agent_provider` 的行）标记 `ai = 1`，`ai_model = agent_model`；
3. 旧无尽榜键（`normal`、`hard:pure`、`abyss3:pure:auto`、`ai:normal:auto` …）全部并入 `endless`：
   同一 `device_hash` 在多张旧榜上都有成绩时**只保留最好的一条**（未判作弊优先，再按 得分 → 波数 → 先提交 → id），其余删除，
   否则改榜键会撞 `UNIQUE(board, device_hash)`；每日榜不动；
4. 换成新的排名索引。

旧 AI 榜的去重键是「设备 + 模型」，并入后同一设备不同模型的旧成绩会各占一行，新提交（「设备 + ai」）不会覆盖它们——数据量很小，可以接受。
旧客户端（缓存的旧版页面）提交的旧榜键在服务端 `normalizeBoardKey` 归一，照常入榜。

## 4. 排行榜与每日挑战

只有三类榜，界面也只有三个分页（无尽 / 每日 / 战役）：

| 榜键 | 说明 | 排名 |
|---|---|---|
| `endless` | 所有无尽成绩**一张榜**：不分难度、魔境等级、纯净、开波方式 | 得分（已含难度倍率 `scoreMul`，难度越高越占优）→ 波数 |
| `daily:YYYY-MM-DD` | 每日挑战，每天一张（界面默认今天，可切到昨天） | 得分 → 波数 |
| `campaign:ch1` / `ch2` / `ch3` | 战役，每章一张；普通 / 困难合并 | **评星** → 得分（困难倍率 1.5，同星时通常排在普通前面）→ 波数 |

- 每行显示难度标签（含魔境等级）、波数 / 评星、「AI 辅助」标记（AI 参战再带模型名）。
- **自定义模式不排名**（参数任意），只记进「我的记录」。固定布局、带自定义参数 / 事件的对局同样不排名。
- 榜键必须与 opts 一致：战役 opts ↔ `campaign:<map>`；无尽 opts ↔ `endless` 或 `daily:<日期>`。
- **战役**：全部结束的战役局都上传；通关 = 打满 20 波且还有生命，评星 = `starsFor(剩余生命, 生命上限)`（≥90% 3 星、≥50% 2 星、否则 1 星），
  失败记 0 星（按得分 / 波数排在所有通关者后面）。生命上限会被增益抬高，所以由客户端带 `maxLives`，服务端只核对 `lives ≤ maxLives ≤ 500` 并重算星数；
  战役难度只能是普通 / 困难。
- **每日挑战**：日期按北京时间（UTC+8）；`seed = dailySeed(day)`，地图 3 天轮换、难度按 7 天轮换（普通/困难/普通/噩梦/困难/普通/困难），所有人相同。
  规则固定为**纯净 + 自动开波 + 技能 1 级**（最多 3 个技能，玩家自选），减少存档养成带来的差距（这条保留：每日挑战页本来就只会这样开局）。
  零点后 2 小时内仍接受前一天的成绩（跨零点打完的局）。每日种子不能用来刷无尽榜。
- 无尽榜允许任意种子（游戏本来就支持玩家自定义种子），所以「刷种子」无法阻止——这是规则的一部分，不是作弊。

### 4.1 AI 辅助

| 对局里用过 | 成绩 | 标记 |
|---|---|---|
| 只用「AI 军师」（只给建议） | 普通成绩 | 无 |
| 「让 AI 替我玩」（任何模式、任何关卡） | 进同一张榜，参与排名 | `aiAssist` → 「AI 辅助」 |
| 「AI 参战」（AI 从第 1 波起全程操作） | 进同一张榜，参与排名 | `agent` → 「AI 辅助」+ 模型名（兜底机器人占比 > 20% 另标「兜底多」） |
| 「AI 参战」中途被你接管 | 进同一张榜，参与排名 | `aiAssist`（带 `botShare`）→ 「AI 辅助」（> 20% 另标「兜底多」） |

**兜底占比（docs/10 §18-6）**：兜底机器人决策 > 20%（`AI_BOT_SHARE_FLAG`）的 AI 辅助成绩**照常收、照常排名**，
服务端存进 `agent_bot_share`，`LeaderRow.botHeavy = true`，榜上和 AI 结算卡片显示「兜底多」（`ui.lb.botHeavy`，四种语言）。
内置策略（`provider = 'scripted'`）本身就是机器人，不标。
目前只有 AI 结算卡片（`src/ui/ai/report.ts`）知道兜底占比；对局中途开关的「让 AI 替我玩」（普通结算面板）还不带 `botShare`，存 NULL、不标。

**硬币自动拾取（docs/10 §18-5）不算辅助**：它是便利设置，不替玩家做任何决策，所以不上报、不标注、不影响排名。

排行榜页的「隐藏 AI 辅助」开关（`hideAi=1`）只看真人成绩。旧的独立 `ai:` 榜已取消（迁移 0003 并入 `endless`）。

### 4.2 自动上传与默认昵称

- 每局结算时自动上传（排行榜页「自动上传成绩」开关，缺省开启；存在 `localStorage` 的 `desk-defense.online.autoUpload.v1`）。
  关掉后结算面板给一个「上传成绩」按钮。断网 / 限流时照旧进离线队列，联网后补传。
- 不再弹框要昵称：没设过时用**默认昵称** = 本地化前缀（玩家 / Player / プレイヤー）+ 设备 id 前 4 位大写，例如「玩家3F9A」；
  排行榜页与结算面板都能改名（改名后下次上传时服务端同步更新该设备在该榜的昵称）。
- 同一局的结算面板重建（例如切换语言）不会重复上传 / 重复记录。

## 5. 防作弊

### 5.1 现在（免费计划）：只做便宜的检查

| 层 | 检查 |
|---|---|
| 版本 | `gameVersion` 必须等于服务端的 `GAME_VERSION`（避免旧客户端 / 改过平衡的成绩混进来） |
| 结构 | 所有字段类型、范围；opts 不得有未知字段、自定义参数、固定布局；技能 / 天赋 id 合法 |
| 榜键 | 与 opts 推导出的榜键一致；每日榜种子 / 地图 / 难度 / 规则一致，且日期有效 |
| 得分重算 | 公式 `round((cleared×100 + kills + lives×50 + gold×0.1 + bonus) × scoreMul)`。<br>带 `cleared / bonus` 时精确比对（`cleared ∈ [wave-5, wave+1]`，`bonus ≤ cleared×100 + kills`）；<br>不带时用区间校验（`cleared` 取最小/最大、`bonus` 取 0/上限） |
| 合理性 | `ticks ≥ 波数 × 3 秒`、`ticks ≤ (波数+1) × 20 分钟`、整局 ≤ 12 小时；击杀 ≤ (波数+1)×2000；无尽模式不可能 `won` |
| 日志 | 原文 ≤ 200 KB / 2 万条；帧号单调不减；**没有晚于结束帧的指令**；指令数 ≤ 30 条/秒 且 ≤ 400 条/波；至少开过一波；手动开波时开波次数 ≥ 撑过的波数；未知指令类型拒绝 |
| 频率 | 每 IP、每设备 10 分钟 10 次 |
| 人机验证 | 配置 `TURNSTILE_SECRET` 后必须带有效 Turnstile token |

> `cleared`（最近清掉的波）和 `bonus`（老师表扬加分）目前是 core 的私有字段，客户端拿不到，所以现在走区间校验。
> 如果 core 以后在 `state.stats` 里公开这两个量，UI 填上即可自动升级为精确校验，服务端无需改动。

这些检查挡得住「手改分数」「伪造请求」「旧版本」「刷接口」，**挡不住**改了客户端逻辑后打出来的、自洽的假成绩。
所以所有成绩先是 `pending`（界面标「待验证」），第二阶段开启后变成 `verified` / `rejected`。

### 5.2 第二阶段：服务端回放（已实现，默认关闭）

提交时已经保存了所需的一切：`seed + opts_json + log_gz + game_version + result_json`。

**校验逻辑**（`src/shared/replay-verify.ts`，纯函数）：
1. 用 `{ ...opts, seed }` 新建 `createWorld`，按与 `replaySync` 相同的规则以固定步长重放：帧 t 先按顺序执行所有 `tick === t` 的指令（一律经 `World.command()`，
   不识别具体指令类型，core 新增指令自动支持），再 `step()`，直到 `result.ticks` 或胜负已分。
2. 下列情况 `rejected`（`reject_reason = "<code>: <英文说明>"`，≤ 300 字符，给运维看）：
   `bad_input`（存储数据解不开）· `log_order` / `log_after_end`（帧号倒退 / 晚于结束帧）· `command_failed`（某条指令重放时失败——客户端日志只记成功的指令）·
   `perk_stuck`（卡在选增益）· `ended_early`（对局提前结束、还剩指令）· `too_long` · `replay_error`（core 抛异常）·
   `mismatch`（`ticks / score / kills / lives / gold / won / 撑过的波数`，战役再加 `stars / maxLives` 与回放不一致）。
3. 只回放 `game_version` 等于服务器当前 `GAME_VERSION` 的行；旧版本的 pending 不处理（保持 pending，可按需批量清理）。
4. 被判 `rejected` 的行不再出现在排行 / 名次 / 总数 / `GET /api/runs/:id` 里（这些查询本来就带 `status <> 'rejected'`），并清掉该榜边缘缓存；
   该设备下次提交任何成绩都会覆盖它（UPSERT 的 `OR runs.status='rejected'`）。
5. 写结论时只改「仍是 pending 的同一个 id」：校验期间同一设备刷新了纪录（UPSERT 会换新 id），新成绩不受影响（结果里记为 `skipped: replaced`）。

**两种跑法：**

| | 线上接口 `POST /api/admin/verify` | 离线脚本 `scripts/verify-runs.ts` |
|---|---|---|
| 计划 | **Workers 付费计划**（一局几万帧的回放要几十 ms～几秒 CPU；免费计划单请求约 10 ms 必然超限） | 免费计划也能用（在你自己的机器上跑） |
| 开关 | `REPLAY_VERIFY=1` + secret `ADMIN_TOKEN`（缺一即 404） | — |
| 触发 | 手动 / 外部定时器（cron、GitHub Actions）带口令调用；每次 `limit` 条 | 导出 → 校验 → 生成 SQL → 自己执行 |

**开启线上接口（由负责人执行）：**
1. Cloudflare 账户升级 Workers 付费计划（Pages Functions 跟随 Workers 的计划与 CPU 上限）。必要时在 `wrangler.toml` 加 `[limits] cpu_ms = 30000`（Pages 支持 `limits` 字段）。
2. `npx wrangler@4 pages secret put ADMIN_TOKEN --project-name desk-defense`（随机长串，如 `openssl rand -hex 32`；不要写进 `wrangler.toml`）。
3. 设 `REPLAY_VERIFY=1`：控制台 Pages 项目 → 设置 → 变量，或在 `wrangler.toml` 的 `[vars]` 里加 `REPLAY_VERIFY = "1"`，重新部署。
4. 调用：`curl -X POST -H "X-Admin-Token: $ADMIN_TOKEN" "https://<域名>/api/admin/verify?limit=10"`，看 `remaining` 归零为止；可以用外部 cron 每几分钟跑一次。
5. 关闭：删掉 `REPLAY_VERIFY`（或改成别的值）即可，接口回到 404。

**离线脚本：**
```bash
npx wrangler@4 d1 execute desk-defense --local --json \
  --command "SELECT id, board, seed, opts_json, result_json, log_gz, game_version FROM runs WHERE status = 'pending'" > pending.json
npx vite-node scripts/verify-runs.ts -- pending.json --sql verdicts.sql      # 可加 --limit N / --any-version / --quiet
npx wrangler@4 d1 execute desk-defense --local --file verdicts.sql           # 线上把 --local 换成 --remote（负责人执行）
```
退出码 0 = 全部通过，2 = 有 rejected。

**还没做（可选）**：前 100 名只显示 `verified`；提交时同步回放（付费计划 CPU 足够时）；Cron Trigger（Pages 不支持 Cron，需要单独的 Worker 定时调用上面的接口）。

> 这就是为什么 **`GAME_VERSION` 必须严格跟随规则变化**（§7）：回放用的是服务器上的当前代码。

### 5.3 限流

固定窗口：`window_start = floor(now / 600 s) × 600`，D1 一条 UPSERT 原子计数：
```sql
INSERT INTO rate_limits (key, window_start, count) VALUES (?, ?, 1)
ON CONFLICT(key) DO UPDATE SET
  count = CASE WHEN rate_limits.window_start = excluded.window_start THEN rate_limits.count + 1 ELSE 1 END,
  window_start = excluded.window_start
RETURNING count
```
`ip:<hash>` 和 `dev:<hash>` 都计数（不短路，换 key 绕不过去），任一超过 10 次即 429。约 2% 的请求顺手删除过期窗口。
存储抽象为 `RateLimitStore`（`D1RateLimitStore` / `MemoryRateLimitStore`），测试用内存实现。

## 6. 隐私

- **不存 IP、不存原始设备 id**：只存 `sha256(HASH_SALT | ip | <ip>)`、`sha256(HASH_SALT | dev | <uuid>)` 的前 32 位十六进制。盐是 secret，泄露数据库也反推不出来。
- 设备 id 是客户端随机 UUID（`localStorage: desk-defense.online.device.v1`），与任何账号无关；清浏览器数据就换一个身份（旧成绩留在榜上）。
- 昵称由玩家自己填（`desk-defense.online.nickname.v1`，独立于存档），服务端清理控制字符 / 零宽字符、NFKC 归一化、1–12 字、简单屏蔽词。
- 公开接口只返回昵称、成绩、地图、时间、回放数据，不返回任何哈希。
- 没有 Cookie，没有第三方统计。开启 Turnstile 时 Cloudflare 会处理人机验证数据。

## 7. `GAME_VERSION` 怎么升

`GAME_VERSION = "<package.json version>+c<CONTENT_REVISION>"`（`src/shared/leaderboard.ts`）。

**任何会改变「同种子 + 同指令 → 同结果」的改动**都要升：数值平衡（`src/config/*`）、波次生成、塔 / 敌人 / 技能 / 事件 / 增益逻辑、随机数用法、得分公式。
做法二选一：
- 小改：`CONTENT_REVISION` +1；
- 发版：升 `package.json` 的 `version`（`CONTENT_REVISION` 可以不动）。

纯美术、界面、音效改动不用升。升级后旧客户端提交会得到 409「游戏版本已更新」；PWA 会自动更新，玩家刷新即可。
过渡期需要同时接受旧版本时，设置环境变量 `ACCEPT_GAME_VERSIONS=旧版本`（逗号分隔），过后清空。

## 8. 运维：需要在 Cloudflare 控制台 / 命令行做的事

1. **创建 D1**：`npx wrangler@4 d1 create desk-defense`，把输出的 `database_id` 填进 `wrangler.toml`（替换 `<填入你的 D1 数据库 ID>`）。
   或在控制台 Workers & Pages → D1 → Create，然后在 Pages 项目 → 设置 → 绑定 → 添加 D1，变量名 **`DB`**。
2. **建表**：`npm run db:migrate:remote`（= `npx wrangler@4 d1 migrations apply desk-defense --remote`）。以后新增迁移文件同样执行。
3. **设置盐（必需）**：`npx wrangler@4 pages secret put HASH_SALT --project-name desk-defense`，填一个随机长字符串（如 `openssl rand -hex 32`）。设好后不要再改，否则同一设备会被当成新玩家。
4. **Turnstile（可选）**：控制台 → Turnstile → 添加站点（域名填 Pages 域名，模式选「托管」或「隐形」），
   - `npx wrangler@4 pages secret put TURNSTILE_SECRET --project-name desk-defense`
   - 站点密钥填到 `wrangler.toml` 的 `TURNSTILE_SITE_KEY`（公开值，`/api/status` 下发），
   - UI 需加载 Turnstile 脚本并调用 `setTurnstileProvider`。不设置 secret 就完全跳过。
5. **部署**：`npm run deploy` 不变——`wrangler pages deploy dist` 会自动编译 `functions/` 并生成只覆盖 `/api/*` 的 `_routes.json`，静态资源请求不消耗 Functions 次数。
6. **Cache API** 只在自定义域名上生效（`*.pages.dev` 上是空操作，功能不受影响，只是每次都查库）。
7. **第二阶段回放校验（可选，付费计划）**：`ADMIN_TOKEN` secret + `REPLAY_VERIFY=1`，步骤见 §5.2；免费计划可以用离线脚本 `scripts/verify-runs.ts`。
8. **日常维护（可选）**：清理 30 天前的每日榜 `DELETE FROM runs WHERE day < '2026-10-01'`（`wrangler d1 execute desk-defense --remote --command …`）；封禁某昵称 / 设备可以直接把行 `status` 改成 `'rejected'`。

## 9. 成本（免费计划）

| 资源 | 免费额度 | 本方案用量 |
|---|---|---|
| Pages Functions 请求 | 10 万次/天（与 Workers 共享） | 每局结算 1 次提交 + 打开排行榜几次查询；静态资源不计 |
| Functions CPU | 约 10 ms/次 | 提交：最大日志（200 KB 原文 / 约 3000 条）解压 + 校验在开发机上 3.5–6 ms；普通对局的日志小得多；查询 < 2 ms。若线上出现 CPU 超限，先把 `LOG_MAX_RAW_BYTES` 调小 |
| D1 存储 | 5 GB | 每行约 5–40 KB（主要是压缩后的日志），每设备每榜一行；10 万行 ≈ 2–4 GB 上限，实际远小于此 |
| D1 读行数 | 500 万行/天 | 前 N 名走索引读 N 行；名次计数读「榜上比你好的行数」；边缘缓存 30 秒 |
| D1 写行数 | 10 万行/天 | 每次提交约 3–4 行（限流 2 + 成绩 1） |
| Turnstile | 免费 | — |

超出免费额度时 Functions 会返回 429/错误，客户端自动把成绩放进离线队列，玩家感知为「暂时无法上传」。

## 11. 游戏内反馈（`POST /api/feedback`）

玩家在「设置」页底部（「版本 · 更新日志」旁）、主菜单底部、对局暂停 → 设置 里点「反馈」，填类型（Bug / 建议 / 其他）、内容（必填，≤ 1000 字）和可选的联系方式（≤ 100 字）。
对话框会把自动附带的信息原样展示给玩家：版本（`APP_VERSION`）、语言、屏幕尺寸（如 `390x844@3`）、当前页面（对局中为 `game/<模式>/<地图>/<难度>`）、浏览器 UA。**不收集其他个人信息。**

| 位置 | 内容 |
|---|---|
| `src/shared/feedback.ts` | 共用：类型、长度上限、限流参数、清洗函数（控制字符 / 零宽字符、按码点截断） |
| `functions/_lib/feedback.ts` · `functions/api/feedback.ts` | 服务端：校验 + 限流 + 写库 |
| `src/meta/feedback.ts` | 客户端：收集环境信息、生成「复制反馈内容」的文本 |
| `src/meta/online.ts` `sendFeedback` | 客户端：发送（走与排行榜相同的 `baseUrl`，原生壳也能发） |
| `src/ui/feedback.ts` | 对话框 |
| `migrations/0005_feedback.sql` | `feedback` 表 |

**请求**（JSON，≤ 8 KB）：

```json
{ "kind": "bug", "text": "第 3 波卡住了", "contact": "qq 12345",
  "deviceId": "<设备 uuid，可选，只用于限流>",
  "context": { "version": "0.3.4", "locale": "zh-CN", "screen": "390x844@3", "route": "game/endless/ch2/normal", "ua": "Mozilla/5.0 …" },
  "turnstileToken": "<开了 Turnstile 时必填>" }
```

**响应**：`201 { "ok": true, "id": "<14 位 id>" }`；错误格式与 §2 相同（`bad_request` / `too_large` / `rate_limited` / `turnstile` / `not_configured`）。

- **校验**：`kind` 必须是 `bug` / `idea` / `other`；正文清洗后为空 → 400；所有字段服务端重新清洗并截断（正文 1000、联系方式 100、UA 300、页面 80 字……），超长不报错直接截断。
- **限流**（两层，任一超限 429）：
  1. `rate_limits` 表固定窗口：`fb:ip:<hash>` / `fb:dev:<hash>` 每 10 分钟最多 3 次，**格式错误的请求也计数**（与提交成绩的 `ip:` / `dev:` 计数互不影响）；
  2. `feedback` 表滑动窗口：同一 IP 哈希或同一设备哈希最近 1 小时已存下的条数 ≥ 6 时拒绝。
- **隐私**：与 §6 相同，只存 `ip_hash` / `device_hash`（加盐哈希），不存 IP 和原始设备 id；联系方式只在玩家主动填写时保存。
- **发不出去时**（离线、本地 `vite dev` 没有 API、原生壳连不上、被限流）：对话框显示错误、「复制反馈内容」按钮和 GitHub Issues 地址 <https://github.com/Owlbay/desk-defense/issues>（链接 + 纯文本）。不进离线队列；关掉对话框后草稿保留在内存里，直到发送成功或刷新页面。
